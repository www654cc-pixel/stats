## 全面审计（全 8 个自定义提交）

- 输出全面审计报告 `audit-report-full.md`，覆盖全部 8 个提交（26 文件，+2678/−122 行）。
- 核心发现 — 性能瓶颈（按严重度）：
  1. **P0**：`PowerFlowPortal` 每 6s fork `/usr/bin/top -l 2`，top 自身遍历全部进程 power，单次峰值 3-8% CPU，是最大开销源。建议改用 `libproc` 的 `proc_pidinfo`+`proc_pid_rusage` 原生 API。
  2. **P0**：`CombinedView.powerTimer`（2s）在 popup 关闭后仍常驻运行，与 PowerFlowPortal 的 2s 定时器重复读取相同数据。建议接入 popup 生命周期或复用 `lastPowerValue`。
  3. **P1**：`ProxyPortal` 每 30s 对所有节点并发 HTTP 测速（`all.forEach { testDelay($0) }`），50 节点 = 50 并发请求。建议改为仅测当前节点 + 展开时测全量。
  4. **P1**：桑基图每 2s 无条件 `needsDisplay`，173 行 draw() 重建所有路径。建议增量重绘（值变化才触发）。
  5. **P1**：磁贴每 1s 无 diff 刷新，无条件格式化 6 组字符串并写入 stringValue。建议加 diff 短路。
- 功能建议（高价值）：汇率磁贴（CNY/RUB/KZT/MXN/GBP）、网络延迟质量指示、日程预览行、热节流指示、磁贴长按快速操作。
- 完成两项 P0 优化后，预计 popup 打开时 CPU 从 3-5% 降至 0.5% 以下。

## 性能优化实施（feature/perf-optimizations 分支）

从 `feature/single-icon-dashboard` 拉出 `feature/perf-optimizations` 分支，完成 5 项优化：

1. **P0-1**：`PowerFlowPortal.readTopProcesses` 用 `proc_pid_rusage`（`ri_user_time + ri_system_time`）两次 200ms 采样替代 `top -o power`。消除每 6s fork 子进程的 3-8% CPU 峰值。显示从 power 值改为 CPU%。标签 "High power" → "Top CPU" / "CPU 占用"。
2. **P0-2**：`CombinedView.powerTimer` 间隔 2s→3s，popup 打开时暂停（PowerFlowPortal 已在刷新相同数据），关闭时立即刷新一次。
3. **P1-1**：`ProxyPortal` 延迟测试从每 30s 全量并发改为：仅测当前节点 + 展开时批量测（5 并发上限，5 分钟缓存）。
4. **P1-2**：`PowerSankeyView.model` 加 didSet 变更检测（功率变化 >0.2W 或状态变化才重绘）。
5. **P1-3**：`MetricTile.set()` 加 diff 缓存，值不变时跳过 stringValue 赋值。
